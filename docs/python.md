# 파이썬 — 셀 편집기 · 실행 엔진 · 실행기 2단

파이썬 연계 프로젝트의 셀 창, 활동 예시 코드, Pyodide 실행 엔진, 실행기 2단 서랍의 원문입니다.

## 먼저 지킬 것

- Pyodide 워커는 `lib/pyRun.js` 한 벌을 나눠 쓰고, 화면을 여는 것만으로 만들지 않습니다(처음 실행할 때).
- 실행은 늘 새 이름 공간에서 합니다. `.py-code` 클래스를 다른 데 쓰지 않습니다.
- 셀 창은 칸을 누르는 길 하나로 엽니다. 실행기 2단과 '활동으로 보내기'는 교사 전용이고, 학생에게 보내기를 되살리지 않습니다.
- 예시 코드는 활동 **이름 → 코드 맵**으로 둡니다(배열로 두지 않음).
- 읽는 자리를 새로 만들면 `tidyCellsHtml`을 거치게 합니다. `pyTarget`은 방송 문서가 아니라 반 문서에 둡니다.

### 파이썬 실행 엔진 · 출력 (실행기 · 코드 셀 공통)

- 학생이 서랍에서 파이썬을 돌리는 곳은 **연계 프로젝트의 코드 셀**
  (`PyCellEditor`, 위 절)이고, 실행기와 **엔진 한 벌**을 나눠 씁니다. 이 절은
  둘이 함께 따르는 약속입니다.
- **엔진은 `lib/pyRun.js` 한 곳**입니다. 워커를 만드는 코드가 실행기
  (`PythonRunner`) 안에 있던 것을 옮겼습니다 — 그대로 복사해 서랍에도 두면
  **Pyodide가 두 벌 뜹니다**(하나가 100MB 남짓). 두 화면은 나란히 열릴 수
  있으므로 한 벌을 나눠 쓰고, 동시에 두 곳에서 돌리지는 않습니다(`"busy"`).
  - **화면을 여는 것만으로 워커를 만들지 마세요.** Pyodide는 CDN에서 10MB
    남짓을 받습니다(처음 한 번, 그 뒤로는 브라우저 캐시). 서랍을 열자마자
    받게 하면 **코딩이 아닌 수업에서도 반 전체가** 그만큼 받습니다. 워커는
    `runPython`을 처음 부를 때 생기고, 그때 `"fresh"`를 돌려주어 부르는 쪽이
    '불러오는 중' 안내를 답니다.
  - 실행기를 닫아도 **워커를 끄지 않습니다** — 서랍과 한 벌을 나눠 쓰므로,
    닫았다고 남의 실행까지 끊으면 안 됩니다. 꺼지는 때는 중단·시간 초과뿐.
  - **실행은 늘 새 이름 공간에서**입니다(`runPythonAsync(code, { globals: 새 dict })`).
    예전에는 Pyodide의 공용 전역에서 돌려 **앞 실행의 변수가 다음 실행에
    남았습니다**(실측: `x = 41`을 돌린 뒤 `print(x + 1)`만 돌려도 42). 같은
    코드가 두 번째에만 돌고, 붙인 결과가 그 코드만으로 나온 것인지 알 수
    없었습니다. 실행기·서랍·파이썬 연계 셀이 모두 이 규칙입니다.
    - `__name__`을 `"__main__"`으로 넣어 둡니다 — 빈 dict면
      `if __name__ == "__main__":`이 NameError로 멈춥니다.
    - 불러온 모듈은 파이썬이 따로 기억해(`sys.modules`) 다시 받지 않습니다.
      새로 만드는 것은 변수가 사는 공간뿐입니다.
- **돌릴 때는 공통 들여쓰기를 걷습니다**(`lib/pyCells.js`의 `dedent` — 파이썬
  textwrap.dedent와 같은 셈). 옛 코드 블록의 '공백 한 칸'(아래 '빈 코드 블록의
  공백 한 칸')이 **이미 저장된 카드에는 그대로** 남아 있어, 안 걷으면
  IndentationError입니다. 옛 카드를 셀로 풀 때도 같은 셈을 씁니다.
- **실행 단축키는 Ctrl(⌘)+Enter** — 실행기와 코드 셀이 같습니다(둘 다
  CodeMirror의 keymap).
- **오류 글은 Pyodide 자신의 줄을 걷습니다**(`tidyTraceback`). 결과가 카드에
  저장되는 글이라 `/lib/python312.zip/_pyodide/…` 두 벌이 늘 붙어 있으면 안
  됩니다.
- **입력값 칸은 코드에 `input(`이 보이는 즉시 뜹니다**(`codeUsesInput` — 코드

    **값을 미리 적어 두는 방식**이라는 것을 누르기 전에는 알 길이 없었습니다
    (브라우저 안에서 한 번에 도는 것이라 실행 도중에 키보드를 기다릴 수
    없습니다). 지금은 **누르면 늘 돌아갑니다** — 칸을 비워 둔 채 돌리면

  - **본문 배치는 두 단이 같습니다** — 에디터 위, 입출력 아래. 좌우로 가르던
    것도 전체 화면이 하던 일이고, 서랍 폭에서는 가를 자리가 없습니다.
  - 폭은 컴포넌트가 **인라인으로** 줍니다(1단 폭 + `LINK_W`). CSS에 못 박으면
    끌어서 정한 폭을 잃습니다. `.py-project`의 flex-basis나 `.py-main`의 gap을
    고치면 `LINK_W`도 함께 고치세요.
  - **여닫힘은 처음 열릴 때와 같은 전환을 씁니다** — `.py-panel`의
    `transition: transform .25s, width .25s`. 한 서랍이 두 속도로 움직이면
    2단만 따로 노는 것처럼 보입니다. `SLIDE_MS`(250)는 이 값과 **같아야**
    합니다 — 닫을 때 프로젝트 칸을 그만큼 더 그려 두는 데 씁니다.
    곧바로 걷어 내면 내용이 먼저 사라지고 폭이 뒤늦게 줄어 두 동작으로
    보입니다. **`.linked` 클래스도 `linkRendered`를 따릅니다**(`linkedOpen`이
    아니라) — 클래스가 먼저 빠지면 아래 `min-width`가 함께 풀려 닫히는 내내
    코드 칸이 403 → 90px로 짜부라집니다(실측).
  - 전환 중에 에디터 칸이 짜부라지지 않게 `--py-body-w`(= 폭 − 37)를 인라인
    으로 주고 `.py-panel.linked .py-body`의 `min-width`로 붙듭니다. 37은
    좌우 여백 18+18 + 왼쪽 테두리 1입니다(`.py-panel`은 border-box — 실측
    440 → 403). 넘치는 만큼은 `.py-main`의 `overflow: hidden`이 가려, 여는
    동안 프로젝트 칸이 **드러나고** 닫는 동안 **가려집니다**.
  - **`.py-body`에 `min-width: 0`이 있어야 합니다.** flex 항목의 기본값
    `min-width: auto`는 내용보다 좁아지기를 거부하는데, 세로로 쌓기만 하던
    때는 부모가 열이라 티가 안 났습니다. `.py-main`으로 감싸 가로줄이 되자
    이 칸이 부모보다 13px 넓어져 잘렸습니다(실측 403 대 416).
  - **크기 조절 손잡이는 2단에서도 그대로**입니다. 끄는 것은 '패널 전체 폭'인데
    state에 담는 것은 에디터·입출력 칸의 폭이라, 2단이면 `LINK_W`만큼 빼고
    담습니다 — 안 그러면 2단에서 끌 때마다 폭이 그만큼 튑니다.
  - **넓히기만 하던 예전 '전체 화면'은 없앴습니다.** 그래서 **연계할 것이 없는
    화면에는 단추가 아예 없습니다**(`canLink` — 교사이고 반·프로젝트 목록·
    사용자가 다 있어야 섭니다). 질문방(`/board`)과 학생 화면이 그렇습니다.
  - 상태 이름도 `linked`, CSS도 `.py-panel.linked`입니다 — `full`로 두면
    '넓히기'로 읽혀 없앤 개념이 이름에 남습니다.
- **2단은 교사에게만 있습니다**(`canLink`에 `isTeacher`). 학생 실행기는 1단
  연습장입니다 — 학생이 활동 칸에 코드를 쓰는 곳은 공부방 카드의 큰 셀 창입니다
  (위 '파이썬 연계 프로젝트의 활동 칸은 셀입니다' 절).
  - **한때 학생도 2단이 있었고, 거기서 '활동으로 보내기'를 눌렀습니다.**
    교사가 고른 곳(`pyTarget`)이 기본 목적지였고 학생은 제 화면에서만 바꿀 수
    있었습니다(`myPick`). 그 보내기가 탈의 원천이었습니다 — 제목으로 짝지어
    엉뚱한 칸에 들어가기(1번에 보냈는데 2번 글이 1번에), 카드 화면이 보낸 것을
    늦게 들여오거나 자동 저장으로 덮어쓰기, 고쳐 놓고 다시 안 돌린 코드에 지난
    결과가 붙기, 잠긴 활동으로 보내기. 학생이 **그 칸에서 곧바로 쓰면** 보낼 일
    자체가 없어 전부 걷었습니다(`pyShareHtml` · `appendToActivity`도 함께).
    **학생에게 보내기를 되살리지 마세요** — 되살리려면 위 탈을 전부 다시 막아야
    합니다.
- **교사 2단이 하는 일은 둘**입니다.
  - **고르면 그 활동을 엽니다**(`openIfLocked` — 위 studyTemplates 절). 고른
    곳은 반 문서의 `pyTarget`에 적어 다음에 열어도 그 자리입니다(학생 화면은
    이 값을 안 읽습니다).
  - **그 자리에서 프로젝트·활동을 만듭니다.** 수업 중에 공부방으로 건너가
    만들고 돌아오면 짜던 코드가 없습니다(화면을 옮기면 실행기가 닫힙니다).
    만든 것은 곧바로 골라 둡니다. 여기서 더한 활동만 **열린 채로
    시작합니다**(`nextActivityLocks`의 기본은 잠김인데, 지금 쓰게 하려고
    만드는 활동이라서).
  - 고르개 둘(프로젝트 ｜ 활동)은 **맨 위 한 줄에 나란히**(`.py-project-picks`,

    줄여 적으므로, **바로 아래 `.py-project-where`가 고른 곳을 온전히 되풀이**
    합니다(잠긴 활동이면 그것도 여기서).
  - 모둠 프로젝트를 고르면 '학생이 서랍에서 쓸 수 없다'는 한 줄을 답니다
