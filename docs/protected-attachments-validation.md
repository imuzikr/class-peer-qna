# 보호된 첨부파일 구현 검증

운영 데이터나 배포 설정은 변경하지 않았습니다. 아래 성능 수치는 한 컴퓨터의
Firebase Auth·Firestore·Storage 에뮬레이터와 HTTP gateway에서 잰 개발 검증값입니다.
실제 학교 네트워크, 리전 간 전송, Cloud Functions 콜드 스타트 성능을 보장하지 않습니다.

## 확인한 동작

- 업로드 직후 임시 파일은 업로더만 열람합니다.
- 본인·담당 교사만 읽는 개인 기록은 같은 반 다른 학생에게도 차단됩니다.
- 비공개 모둠 카드는 해당 모둠원만, 1:1 쪽지는 해당 학생과 담당 교사만 읽습니다.
- 질문방 이미지는 다른 반의 등록 회원도 보며, 비로그인과 앱 프로필 없는 Auth 계정은 거부합니다.
- 파일 번호를 남의 공개 글에 넣는 것만으로 비공개 파일 권한을 위조할 수 없습니다.
- 수업 방송에 명시적으로 공개한 파일만 해당 반이 볼 수 있고, 방송 종료 후에는 원래 권한을 따릅니다.
- 원문에서 이미지 참조를 제거하면 이후 서버 다운로드 요청은 거부됩니다.
- Storage 객체 직접 읽기·metadata·토큰 조회와 레지스트리 위조가 차단됩니다.
- 새 GCS 객체에는 공개 Firebase 다운로드 토큰이 없습니다.
- 파일 Range 전송을 지원하고, 외부 비로그인 요청에는 그림 대신 인증 오류를 반환합니다.
- 본문 저장 이후 연결 실패는 사용자별 재시도 대장에 남기고 글을 중복 생성하지 않습니다.
- 편집기의 Blob 주소는 저장되지 않으며 원래 첨부 식별자로 직렬화됩니다.
- 인쇄 전에 보호된 이미지를 권한 확인해 읽고, 실패하거나 늦게 끝나는 요청의 사용권도 정리합니다.

## 자동 검증 결과

단위·UI 회귀 시험 337개, Firestore·Storage 보안 규칙 시험 507개가 통과했습니다.
린트와 프로덕션 빌드도 통과했습니다. 아래 pilot은 실제 에뮬레이터의 인증·규칙·파일
전송을 묶어 검증하며, 운영 프로젝트를 대상으로 실행하지 않았습니다.

## 로컬 성능 비교

파일 256KiB, 다운로드 각 20회·업로드 각 10회입니다. 압축·파일 선택 UI 시간은 제외했습니다.
기존 업로드는 Firebase SDK의 업로드와 getDownloadURL 요청을, 새 업로드는 인증 gateway의
비공개 저장과 파일 레지스트리 생성을 포함합니다. 결과 원문:
[protected-attachments-pilot.json](validation/protected-attachments-pilot.json).

| 항목 | 중앙값 | p95 |
| --- | ---: | ---: |
| 기존 토큰 URL 다운로드 | 2.79ms | 8.96ms |
| 권한 검사 다운로드 | 16.52ms | 46.93ms |
| 기존 인증 업로드 | 30.37ms | 39.99ms |
| 비공개 gateway 업로드 | 21.20ms | 25.80ms |

새 다운로드에는 실제 권한 검사 비용이 생겼습니다. 새 업로드가 이 로컬 실행에서 더
빨랐다는 결과를 운영 속도 향상으로 해석하지 않습니다. 브라우저는 같은 사용자의
동일 이미지 요청을 합치며 최대 6개를 동시에 요청하고, 화면에서 재사용한 Blob을
매번 다시 다운로드하지 않습니다. 인증·사용자·반·대화방·경로 전환 시 캐시를 정리합니다.
이미 받은 이미지 사본을 회수하는 기능은 아니며, 서버는 새 다운로드마다 본문 권한을 확인합니다.

## 재현

루트와 functions/, tests/rules/ 의존성을 설치하고 Java 21 이상을 준비합니다.

```bash
npm run test:attachments:pilot
npm run test:rules
npm run test:unit
npm run lint
npm run build
```

pilot은 demo- 프로젝트와 loopback 에뮬레이터 주소가 아니면 실행을 거부합니다.
운영 자격 증명이나 실제 버킷을 사용하지 않습니다. 에뮬레이터의 토큰 metadata 삭제는
운영 GCS와 다르므로 명시적 관리자 revoke endpoint로 옛 URL의 차단을 별도로 확인합니다.
운영 도구는 실제 metadata 제거·비로그인 URL 요청 검증을 모두 요구합니다.

## 운영에 적용하기 전

Firebase 관리자 인증이 연결된 환경에서 [전환 절차](protected-attachments-rollout.md)를
수행해야 합니다. 서버 배포 전에 frontend만 배포하면 새 업로드가 실패할 수 있습니다.
기존 토큰 URL은 이관 전까지 호환 표시로 남습니다. 코드·로컬 시험 통과만으로
운영 이미지가 이미 보호됐다고 표시하지 않습니다.
